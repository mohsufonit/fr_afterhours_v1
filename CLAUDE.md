# CLAUDE.md — After Hours (Fableroom × Three Sixty)

Handoff context for any Claude Code session opening this folder cold. Read this file fully before touching `after-hours.html`. If you're tempted to "clean up" or "fix" something that looks unconventional, check the **Do Not Reverse** list (section 6) first — it is probably intentional.

---

## 1. Project Overview

This project is a single landing page for **After Hours**, a leather-goods collection by **Fableroom × Three Sixty** (Hosting & Bar, Furniture, Leather Accessories categories, unified by four leathers: Waxy, Croco print, Shagreen, Hair-on-hide).

- **Deliverable:** `after-hours.html` — one self-contained file in the project root. This is the entire product.
- **Hard constraint:** it stays a single HTML file with inline `<style>` and `<script>`. No build step, no bundler, no framework, no external JS/CSS libraries. Do not introduce one without being explicitly asked.
- Supporting files already in place: `brand-fonts.css` (real brand type, self-hosted `@font-face`), `assets/img/` (real product photography), plus reference PDFs and raw asset folders (see section 8).

---

## 2. Tech Constraints

- **No framework.** Vanilla HTML/CSS/JS only, all inline in `after-hours.html`.
- **Fonts:** loaded via one line, `<link rel="stylesheet" href="brand-fonts.css">` — never re-inline `@font-face` rules or swap back to a Google Fonts CDN link. Resolved through CSS custom properties:
  - `--font-display` → `'IvyPresto Display', Georgia, 'Times New Roman', serif`
  - `--font-body` → `'HK Grotesk', system-ui, -apple-system, 'Segoe UI', sans-serif`
- **Palette** (in `:root`): `--licorice:#260B0F`, `--deep:#1C0810`, `--caramel:#BF7E45`, `--bone:#D9D2BF`, `--grey:#736C58`, `--off:#F5F2EC`, plus `--ink`, `--ink-soft`, `--line`, `--line-dark`.
- **Spacing token system** (in `:root`): `--space-xs`, `--space-sm`, `--space-md`, `--space-lg`, `--sec-pad`, `--sec-pad-lg`. This is the single source of truth for section vertical padding and grid/flex gaps across the whole page. **Any new section or component must reuse these tokens.** Writing a fresh one-off `clamp()` value for padding or gap instead of reusing a token is a regression — it re-breaks the spacing consistency pass that was done deliberately.
- **Images:** every real photo uses `<img class="ph img-cover" src="assets/img/...">`. `.img-cover` is a small utility (`width/height:100%; object-fit:cover; display:block`) added *alongside* the older `.ph` gradient-placeholder system specifically so the existing `.ph`-keyed hover/position/transform CSS (built for gradient `<div>` placeholders) keeps working unchanged on real `<img>` elements. Never strip the `.ph` class off an image just because it's "not actually a placeholder anymore" — it's load-bearing CSS wiring, not a naming leftover.
- **Responsive breakpoints in use:** 1100px, 900px, 600px (desktop → tablet → mobile), plus a `prefers-reduced-motion` block. The two viewports actually tested during this build were **390×844** and **1920×1080** — verify against those first if you change layout.

## 3. Locked Design Decisions

Each of these was a deliberate choice made after discussion, not a default. Do not silently reverse any of them.

- **Hero has zero overlay.** No headline, no tagline, no CTA button, no scrim/shade `<div>` on top of the hero video. **The hero "video" is no longer a `<video>` element — it's two animated WebP images** (`.hero-video.desktop`/`.mobile`, swapped via CSS at the 900px breakpoint), converted from the original MP4s with ffmpeg (`scale=1280:-2`/`scale=-2:960`, `fps=15`, `-q:v 50 -compression_level 6 -method 6`) and living at `assets/video/hero-desktop.webp` (5.6MB, was 32MB) / `hero-mobile.webp` (3.4MB, was 34MB). *Reason: the raw MP4s were too large to reasonably serve/commit (and were previously `.gitignore`d entirely, silently 404ing on the deployed GitHub Pages site) — explicit ask to "convert the video to a webp ... optimise it."* Since `<img>` has no `play()`/`pause()` API, reduced-motion no longer pauses the animation — instead JS swaps `src` to a static poster frame (`data-poster` attribute → `hero-desktop-poster.jpg`/`hero-mobile-poster.jpg`, first frame extracted via ffmpeg). Don't revert to `<video>`/MP4 for the hero, and don't remove the `data-poster` swap — it's the only reduced-motion affordance available for an animated-WebP hero.
- **`#materials-filter` and `#hosting` are intentionally swapped from their original build.** `id="materials-filter"` = the "Materials" browse-by-leather section (banner + 4 leather-type tabs + an overlapping product row). `id="hosting"` = the real Hosting & Bar category section. *Reason: the two sections were re-purposed mid-project; nav links and category tiles already point at the correct one via these ids — swapping them back would silently break navigation.*
- **`.category-split` is the shared component for all three category sections** (`#hosting`, `#furniture`, `#accessories`): `.cs-visual` (banner image) + `.cs-panel` (eyebrow, `h2`, one-line `.cs-sub`, then a `.sub-grid` of 1:1 `.sub-tile` subcategory tiles). Hosting and Furniture are banner-left/panel-right (DOM order = visual order). **`#accessories` is mirrored on desktop only** — `#accessories .cs-visual{order:2}` / `#accessories .cs-panel{order:1}` puts the banner on the right and tiles on the left at ≥901px; both are reset to `order:0` inside the `900px` breakpoint so mobile stacks in natural DOM order (banner, then panel). *Reason: explicit ask to reverse Accessories specifically, desktop-position-only — "mobile colour is what needs to change" (that's the `.trust-break` background, not this).* Don't extend the mirroring to Hosting or Furniture, and don't let the `order` swap leak into the mobile single-column breakpoint.
- **`.sub-grid` is `display:flex;flex-wrap:wrap;justify-content:center`** (not CSS grid) specifically so a trailing incomplete row centers instead of stretching or hugging the left edge — `.cols-3`/`.cols-4` set a `flex-basis` per tile instead of `grid-template-columns`. *Reason: explicit ask — "if it has only two or three product cards then it needs to be middle aligned."* Don't switch this back to `display:grid`, it will re-break the centering.
- **Every `.sub-grid` now has a minimum of 5 tiles**, still capped at 4 per row / 2 rows: Hosting & Bar = 6 (`cols-3`, 3×2), Furniture = 5 (`cols-4`, 4+1 — the 5th, "Ottomans", is a placeholder reusing `sub-dining-chairs.jpg` since no dedicated photo exists yet), Accessories = 8 (`cols-4`, 4×2). *Reason: explicit "minimum of five product cards there even as a placeholder its fine."* The Furniture 5th tile is exactly what exercises the centered-incomplete-row rule above.
- **Category-split panel background alternates dark → white → dark** across Hosting & Bar → Furniture → Accessories (unchanged by the Accessories position-mirroring above — only left/right placement flipped, not the panel's own dark colour). *Reason: explicit alternation request; Hosting & Bar's color was an extrapolation to keep the three-section rhythm consistent since only Furniture/Accessories were named explicitly — flag if this should instead match one specific section.*
- **These three category sections use subcategory-navigation tiles, not product/SKU cards.** No add-to-bag, no wishlist anywhere in `#hosting`, `#furniture`, or `#accessories`. *Reason: explicitly replaced product grids with subcategory tiles to reduce scroll depth and match a reference layout.*
- **`.tile` (3 main `#categories` tiles) and `.sub-tile` (category-split subcategory tiles) have no darkening veil and no solid caption plate.** This went through three iterations: (1) full-tile veil → (2) veil removed, heavy 3-layer `text-shadow` added, reported as a "dark glow" → (3) glow replaced with a solid caption-plate background → (4) **plate also rejected** ("move the brown box ... in that area" — read after the fact as "get rid of it"), settled on a single defined-edge `text-shadow` (`0 1px 3px rgba(0,0,0,.6),0 2px 10px rgba(0,0,0,.5)` — a hard edge, not a diffuse halo) directly on `.tile .cap .k`/`h3`/`.go`, same treatment `.sub-tile .sub-label` already used successfully. `.tile .cap`'s position stays `left/right:22px;bottom:22px` (anchored bottom-left-ish, not flush corner). The `.k` eyebrow line (e.g. "7 STYLES · 15 PIECES") is **hover/focus-only again** (`opacity:0` default, `opacity:1` on `.tile:hover`/`:focus-visible`) — forced back to always-visible only inside the `≤600px` mobile breakpoint, where hover doesn't apply. `.tile .cap h3` font-size was also reduced 5% (`clamp(28px,2.9vw,42px)` → `clamp(27px,2.76vw,40px)`). `.sub-tile .sub-label` keeps its plate-free `text-shadow` + circular `.arrow` badge (bottom-right, `rgba(28,8,16,.5)`, turns caramel on hover/focus) unchanged. *Reason: iterative explicit corrections across two follow-up messages — first "remove all the overlays", then "why is there a dark glow ... remove", then "move the brown box ... to bottom left ... and earlier we had this styles and pieces coming when hovered lets have that only."* Don't reintroduce a full-tile veil, a solid caption-plate background, or an always-visible eyebrow line on desktop — all three were tried and explicitly walked back.
